# Native Scope B/C/D tape replay

`ScopeModelReplay` and `run_scope_model_replay(request, absolute_new_directory)`
connect the full shared Scope response contract to an independent native PAPER
owner. This is local fixture plumbing. It is not authentic model/data acceptance,
full A/B/C/D comparison or a runtime feed adapter.

The request freezes the sealed Scope tape, watch instructions, owner and family
loss policies, entry policy, costs and a role-specific B/C/D script.
B uses the separate [choice-only contract](OPTIONS_SCOPE_COMPARISON.md); C/D use full entry reasoning. D additionally requires the
full Scope position policy. Carry, absent costs, incomplete Scope enrollment and
mismatched roles are rejected before output creation. The deterministic A tape/watch
validation is reused as validation only; its model-off projection is never executed
or persisted. Each run creates its own journal, venue, cash and reservations.

## Explicit enrollment and scheduling

The native coordinator accepts the exact `ScopeReplayModel` or B
`ScopeShortlistModel` only with a
`scope-native-tape-model-v1` enrollment binding tape, request and script hashes.
It freezes this additional configuration in the new owner. The old adapter and
unbound new adapter remain rejected. Existing serialized configurations do not gain
new fields. No key file, authenticated call or model authority is involved.

The scheduler delivers all receipts at a timestamp before releasing a model result
at that timestamp. Native reconciliation, fills, mandatory protection and watch
actions continue while the model is pending. Additional entry/management cycles
are skipped while a prior task is pending. The original request duration and packet
expiry govern model timeliness; virtual delay cannot renew a lease. Native isolated
worker limits remain unchanged.

For a Scope selection, the fresh-input reader returns only the latest complete
Scope observation already delivered for that exact play. It never merges cached
prices into older context or rewrites a source clock. The report records the read's
sequence, event/input hashes, tape hash and virtual time. Native paid admission
runs after known usage settlement, using the owner's current revision and balances.
Every required source clock must advance; immutable Scope terms, quantity, fee
ceiling and the original approval deadline remain binding. No rejected selection
falls through to another candidate.

Model proposals remain distinct from approval, order attempts and actual fills.
Only a later executable receipt can fill an attempted order. D management uses the
original native position packet and supports MAINTAIN, TIGHTEN and EXIT_ALL;
independent mandatory exits remain active.

## Accounting and retained evidence

The output includes `inputs.json`, independent native databases, `native.json` and
`report.json`. The portable native exporter reconstructs original attribution,
entry and management charges, execution fees, cash, reservations, loss controls and
explicit data/host allocations. For this new frozen replay enrollment, a closed
position waits for any pending management decision to become terminal before its
loss record can be consumed. Known usage is charged immediately, but the eventual
applied/rejected attribution must also be stable. The scheduler refreshes native
loss controls at completion, without waiting for another market receipt. Existing
cohort loss-record serialization and consumption remain unchanged.
Unknown model or operating costs remain unknown;
open exposure cannot acquire a realized net result. Stored replay configuration
validates the script binding and C/D management role. Its declared tape/request
hashes identify the runner's retained inputs; the portable native export alone is
not independent attestation of tape acquisition.

A failed/interrupted run retains `interrupted.json` and its native evidence rather
than a successful report. Output creation is exclusive; it never resumes or
replaces an existing account. Native owner recovery remains responsible for
interrupting pending slots without retry; the runner itself is create-only.

Reports explicitly withhold comparison and economic conclusions. B shortlist and
matched independent A/B/C/D comparison/export now use the separate contract linked
below. Continuous Scope runtime and the separate [combined carry series](OPTIONS_SCOPE_CARRY_SERIES.md)
are implemented. Remaining work is family/mixed stock-options plumbing. Final UI and authentic PAPER testing
follow completion of that plumbing. LIVE stays disabled and the deployed
experiment remains frozen.

## Independent Scope comparison continuation

enrolled choice-only B and matched independent one-session native replay/export.
The historical runners and C/D contracts described above retain their original
versions and rejection boundaries. The separate wrapper preserves unknown costs,
all native fees/charges and inconclusive economic status. Continuous Scope runtime
and separately enrolled carry replay/export are implemented. Remaining family/mixed
plumbing and authentic acceptance remain open.
