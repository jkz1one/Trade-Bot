# Independent Scope A/B/C/D fixture comparison

`app.options.scope_comparison` connects four separately funded native owners to one
sealed Scope tape and the same ordered watch instructions. `ScopeComparison`
requires an A `ScopeTradingReplay`, B/C/D `ScopeModelReplay` requests and four
unique population IDs and account IDs. Call
`asyncio.run(run_scope_comparison(request, new_absolute_directory))` from an
installed wheel. This is create-only offline fixture plumbing; it starts no
service and makes no authenticated provider, model or broker calls.

## Roles and enrollment

| Arm | Frozen role |
| --- | --- |
| A | Original deterministic family priority, with no model calls. |
| B | SELECT/HOLD among admitted ordinary candidates and the fixed Scope plan; no replacement geometry. |
| C | Full shared entry reasoning, including the unchanged fixed Scope selection. |
| D | Exactly C's declared entry decisions, delays and usage, plus separately paid management. |

B uses `ScopeShortlistScript`, `ScopeShortlistDecision` and `ScopeShortlistModel`.
Its versioned script permits only entry SELECT/HOLD/UNKNOWN; SELECT names either
the supplied Scope plan or an indexed Degen/Swing candidate. Management slots,
replacement geometry, quantity and unused selection fields are rejected. The
native receipt uses `scope-fixed-shortlist-v1`, `shared-scope-shortlist-v1` prompt
identity and `shared-scope-shortlist-plan-v1`. SELECT is represented as ENTER in
this full native receipt; the retained B script identifies the restricted choice
role. It is not a C plan with invented targets or a zero-charge A decision.

B reuses the complete original packet/request, native usage settlement and stored
receipt validation. For ordinary families, fresh admission preserves the exact
original proposal and its price, quantity, debit, full-premium and approval ceilings.
No model target or horizon is created. Existing native family/session protection
remains authoritative, and dispatch rechecks the full paid receipt even though
there is no model target protection record. For Scope, the unchanged fresh owned
post-cost review must advance required source observations while retaining original
terms, account revision and approval deadlines. B is restricted to explicit local
tape enrollment; the normal authenticated runtime and legacy adapters remain blocked.
The previous C/D script and plan identities are unchanged.

## Matching and independent execution

Validation precedes output creation. Every arm must retain the exact tape, watch
instructions, market/risk limits, original capital, execution fees, loss controls,
family priority and explicit data/host allocation. Only the allowed role fields and
owner identities differ. B/C/D share model pricing/budgets and worker limits; C/D
entry policy and every declared entry script match. D's management policy remains
separately frozen. Carry is still rejected by the underlying Scope runner.

Each arm receives new native journal and venue files, cash, reservations, fill
liquidity accounting, model attempts and loss state. The runner executes them
serially with independent virtual clocks; it never copies one arm's selection,
reached opportunities, balances or fills into another. Different holdings can
cause different opportunities to be reached or skipped even with matched scripts.
Every declared request and the native cycles/proposals/reviews/attempts/fills remain
in the retained inputs and export evidence. Original native restart/no-retry rules
remain in force; the comparison runner itself cannot resume or overwrite an output.

## Comparison and portable reconstruction

`comparison.json` contains the normalized request, four native exports, comparison
report and a `comparison_hash`. Retain that hash independently and call
`verify_scope_comparison(bundle, expected_comparison_hash)` to reconstruct each
native export and the comparison. Verification checks exact owner/strategy/config
bindings, B/C/D tape/request/script enrollment, completed tape accounting boundaries,
operating allocations and recomputed totals. A's tape relationship is retained in
the comparison inputs and runner evidence, not a new legacy native enrollment.
Hashes and native reconstruction do not independently attest tape acquisition or
prove that an exported journal was produced by authentic data/model calls.

The report retains each account's native full-cost accounting, model costs,
execution fees, allocations, orders, outcomes, loss controls and final ledger.
`net_difference_vs_a` uses exact decimal arithmetic. It is published only when
**all four** accounts have complete flat accounting. Open/unresolved exposure,
unknown model usage or unknown operating costs remain explicit; paired net results
are withheld for the whole comparison while the other accounts' known results
remain visible. No costs are pooled, netted away or filled with zero.

`COMPLETE_FLAT_COMPARISON` means complete supplied-fixture arithmetic. The economic
conclusion remains `INCONCLUSIVE`; benchmark evaluation is explicitly absent.
