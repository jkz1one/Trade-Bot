# Continuous native mixed runtime inputs

The explicit `mixed-runtime-inputs-v1` policy binds the existing continuous PAPER
runner to one native mixed owner and frozen stock selection policy. Its separate
`mixed-normalized-fixture-v1` envelope carries CYCLE, MARKET or WATCH deliveries.
Legacy option and Scope envelopes still reject shares. Mixed frames cannot enter
an old runtime, and the new envelope cannot silently enroll an old owner.

## Frozen settings and delivered inputs

Runtime settings bind native stock limits, original source policy, paid entry and
optional management, and any existing Scope/option carry policy. The installed
create-only initializer creates one venue balance and journal with those exact
stock limits. Restart uses the same configuration, native ownership and restore
fence. The common runner reports `MIXED_PAPER_FIXTURE`; this does not enable LIVE.

Each CYCLE supplies the exact frozen stock quote universe plus completed current
strategy evidence. Flat stock Swing selection still requires its original complete
daily/hourly bundle and catalyst coverage. MARKET and WATCH deliveries may contain
stock quotes, but cannot smuggle in replacement stock source bundles. Native Scope
watch instructions retain their existing explicit action keys and original session
deadlines. Scope evidence requires matching Scope enrollment.

The private input file remains size bounded, owner-only and regular, with symlink,
concurrent-write and permissions checks. Packet population, recorded time, source
availability, original instrument identities and the contiguous delivered sequence
are validated before use. Changed, missing, foreign or interrupted inputs block
entry and cannot become a fresh model approval. Quotes that remain delayed or
incomplete do not gain native tradability by being recorded.

Every mixed delivery is retained with its original packet/hash, acceptance clock
and completion status in the native journal. Optional Scope action receipts remain
linked separately to the actual watch action. A delivered packet never represents
a fill. The read-only verifier reconstructs the full prefix, including an interrupted
last acceptance, without reading the current file or gaining execution authority.

Paid stock entry and management use a reader bound to the latest fully delivered
packet. It waits for the current independent protection tick, checks native runtime
readiness, halt state, exact sequence/hash and original quote identity, and then
returns the retained quote. It cannot reread an unconsumed file, skip a pending watch
action or extend the request's original deadline. Scope paid refresh retains its
existing native admission and the same completed-tick boundary.

## Independent protection and original sources

One common native snapshot determines whether the owner holds shares or options.
The supervisor then applies the matching native protection path without a second
funded account or duplicated snapshot. Stock stop, target and time protection runs
on MARKET deliveries between five-minute decisions, including while a paid worker
is waiting. Missing input still performs reconciliation and preserves native exit
latches; it cannot invent a quote or release an unresolved order.

Fresh executable stock bid observations also retire locked original Swing sources
when their invalidation or first objective is consumed. A rebound or later CYCLE
cannot erase that terminal. Delayed, incomplete, foreign or stale quotes cannot
retire a source. The original fixed reference, objectives, carry source and horizon
remain unchanged; current quotes never reconstruct a replacement strategy.

The existing durable slot claims prevent catch-up decisions and repeated calls.
An interrupted delivery or runtime remains blocked after restart. Signed recovery
retains the existing native account/revision and protection checks; receiving a
healthy packet does not silently resume admission. Actual fills and funds settlement
still arrive through explicit native venue receipts. Session rollover preserves
the original cash, unsettled proceeds, full cost history and carry holdings.

## Boundaries and verification

This is normalized offline fixture plumbing. It performs no authenticated feed,
model or broker call during verification. No dependency or deployment change is
required. Final UI/visual and authentic data/model/host/economic/PAPER acceptance
remain separate, and LIVE remains disabled.

[Common mixed tapes and independent native A/B/C/D replay/export](MIXED_REPLAY.md)
now bind separate complete contracts and native full-cost evidence. Old market-tape
and comparison consumers continue rejecting mixed inputs. The settled plumbing is
connected; final UI/visual and authentic acceptance remain separate.

`test_mixed_runtime.py` covers native stock entry/fills and fast protection, held
management during independent ticks, delivered refresh, explicit Scope/option/stock
choices, source retirement, private packet/enrollment failures, restart and actual
funds settlement. Use the [isolated installed-wheel procedure](OPTIONS_TESTING.md).
The latest [status entry](SLICE2_STATUS.md) records completed final-wheel evidence.

## Opt-in quote-driven simulated fills

A newly enrolled mixed runtime may explicitly set
`"simulated_fills": "mixed-quote-fills-v1"`. The default is absent and preserves
existing frozen policies. The runtime applies validated delivered quote evidence
before reconciliation/protection, using the existing native simulated venue;
settlement remains explicit. [Behavior, limits and current provider blocker](MIXED_QUOTE_FILLS.md).
This flag does not acquire market data or make an offline fixture a connected
Robinhood PAPER service.
